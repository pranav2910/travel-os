# Terraform: the AWS estate for travel-os

Layout: reusable modules under `modules/`, one root per environment under `environments/`, and a
one-time `bootstrap/` for the remote state bucket. Nothing here contains an account id, region,
VPC id, password or secret: regions and sizes are variables per environment, account ids come from
`data.aws_caller_identity`, passwords are generated by `random_password` straight into Secrets
Manager (marked sensitive), and the model API key is a placeholder whose real value is set with
the AWS CLI and never read back by Terraform.

```
bootstrap/          S3 state bucket + DynamoDB lock table (apply once per account)
modules/network     VPC, 3 AZs x {public, private, database} subnets, IGW, NAT (per AZ or single), flow logs, S3 endpoint
modules/kms         customer-managed keys (eks, rds, msk, s3, secrets, cache) with rotation
modules/eks         cluster (private endpoint, secrets encryption, audit logs), OIDC provider, 3 managed node groups, addons
modules/aurora      Aurora PostgreSQL Serverless v2, managed master password, encrypted, IAM auth, PI
modules/msk         MSK 3 brokers across AZs, TLS + IAM auth, KMS at rest, auto.create.topics=false
modules/elasticache Redis (gated: no service uses it yet), multi-AZ, encrypted, auth token in Secrets Manager
modules/secrets     per-service credentials in Secrets Manager, generated, never in values or git
modules/irsa        IAM roles for service accounts: External Secrets, EBS CSI, audit (S3), ...
modules/s3          audit archive bucket (versioned, SSE-KMS, lifecycle, no public access)
modules/ecr         one repository per service (immutable tags, scan on push) for EKS pulls
environments/{dev,staging,prod}   composition + sizes; backend config passed at init time
```

## Usage

```bash
cd infrastructure/terraform/bootstrap && terraform init && terraform apply     # once per account
cd ../environments/dev
terraform init -backend-config=backend.hcl                                    # copy backend.hcl.example
terraform plan -out=plan.tfplan && terraform apply plan.tfplan
```

Validation without an account (what CI runs): `make tf-check` = `terraform fmt -check -recursive`,
`terraform init -backend=false && terraform validate` for every root, `tflint`, `trivy config`.

## After apply (dev)

1. `aws secretsmanager put-secret-value --secret-id travelos/dev/llm-gateway/anthropic --secret-string '{"provider":"anthropic","api_key":"..."}'`
2. `aws eks update-kubeconfig --name $(terraform output -raw cluster_name)`
3. Install External Secrets Operator with the IRSA role from `terraform output irsa_role_arns`, create the
   `aws-secrets-manager` ClusterSecretStore.
4. Run the database bootstrap Job (creates one role + database per service from the generated secrets).
5. `helm upgrade --install travelos deploy/helm/travelos -f deploy/helm/travelos/values-eks.yaml --set global.image.tag=<sha>`
   with endpoints from `terraform output`.
